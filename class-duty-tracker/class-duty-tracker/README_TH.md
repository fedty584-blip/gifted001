# ระบบเช็กชื่อทำเวร (Class Duty Tracker)

เว็บแอปภาษาไทยสำหรับห้องเรียนเดียว สร้างด้วย Cloudflare Workers + Cloudflare D1 + Cloudflare R2

## ฟังก์ชันที่มีในชุดนี้

- Dashboard รายเดือน, ปฏิทิน และกราฟสัดส่วน
- เช็กชื่อรายวัน: ทำเวรแล้ว / ไม่ทำเวร / ลาหรือได้รับยกเว้น
- วันไม่มีบันทึกจะไม่ถูกนับเป็นวันไม่ทำเวร
- เพิ่ม/แก้ไข/ปิดใช้งานรายชื่อนักเรียน โดยคงประวัติเดิม
- บัญชีแอดมินหลายบัญชี ชื่อผู้ใช้/รหัสผ่านแยกกัน และสิทธิ์เท่ากัน
- ตั้งค่าบัญชีแรกด้วย Bootstrap Secret ที่เก็บใน Worker Secret
- บันทึกประวัติการแก้ไข
- รายงานรายเดือน, CSV ที่เปิดด้วย Excel ได้, พิมพ์/บันทึกเป็น PDF ผ่านหน้าต่างพิมพ์ของเบราว์เซอร์
- ดาวน์โหลดข้อมูลสำรอง JSON ด้วยตนเอง
- สำรองข้อมูลอัตโนมัติรายวันไปยัง Cloudflare R2 ผ่าน Cron Trigger
- วันหยุดเสาร์–อาทิตย์และวันหยุดประจำปีที่มีวันที่แน่นอนถูกคำนวณให้อัตโนมัติ; วันหยุดที่ขึ้นกับปฏิทินจันทรคติหรือประกาศประจำปีให้แอดมินเพิ่ม/แก้ไขในปฏิทิน

## สิ่งที่ต้องมี

1. บัญชี Cloudflare
2. Node.js LTS ติดตั้งในคอมพิวเตอร์
3. Terminal / PowerShell
4. Wrangler CLI (ติดตั้งจากคำสั่งในขั้นตอนด้านล่าง)

## ขั้นตอนติดตั้งทีละขั้น

### 1) เปิดโฟลเดอร์โปรเจกต์

แตก ZIP แล้วเปิด Terminal ในโฟลเดอร์ `class-duty-tracker` ซึ่งมี `wrangler.toml` อยู่

### 2) ติดตั้ง Wrangler และล็อกอิน

```bash
npm install -g wrangler
wrangler login
```

เบราว์เซอร์จะเปิดให้อนุญาตการเชื่อมต่อ Cloudflare

### 3) สร้าง D1 database

```bash
wrangler d1 create class-duty-tracker-db
```

คำสั่งจะแสดง `database_id` ให้คัดลอก แล้วเปิด `wrangler.toml` แทนที่ `REPLACE_WITH_D1_DATABASE_ID` ด้วย ID จริง

### 4) สร้าง R2 bucket สำหรับสำรองข้อมูลอัตโนมัติ

```bash
wrangler r2 bucket create class-duty-tracker-backups
```

จากนั้นใน `wrangler.toml` เปลี่ยน `REPLACE_WITH_R2_BUCKET_NAME` เป็น `class-duty-tracker-backups` หรือชื่อ bucket ที่สร้างจริง

> ไฟล์สำรองรายวันจะอยู่ใน R2 ภายใต้ `daily/YYYY-MM-DD.json` ควรจำกัดสิทธิ์ bucket และดาวน์โหลดไฟล์สำรองสำคัญเก็บไว้อีกที่หนึ่งด้วย

### 5) สร้างตารางฐานข้อมูล

```bash
wrangler d1 migrations apply class-duty-tracker-db --remote
```

หากต้องการทดลองบนเครื่องก่อน ให้ใช้ `--local` แทน `--remote` แต่ข้อมูล local กับ production จะแยกจากกัน

### 6) ตั้งค่า Secret สำหรับสร้างแอดมินคนแรก

สร้างรหัสติดตั้งยาวและเดายาก (อย่าใช้รหัสผ่านปกติ) แล้วรัน:

```bash
wrangler secret put BOOTSTRAP_SECRET
```

ใส่ค่า secret ใน prompt ของ Wrangler โดยไม่ต้องเขียนลงในไฟล์โค้ดหรือแชร์ให้ใคร

### 7) ทดสอบในเครื่อง

```bash
wrangler dev
```

เปิด URL ที่ Wrangler แสดง จากนั้นหน้าแรกจะให้ตั้งค่าบัญชีแอดมิน โดยใช้ค่า `BOOTSTRAP_SECRET` ที่ตั้งไว้กับ Worker remote ไม่ได้แชร์กับ local อัตโนมัติ หากต้องการทดสอบ local ให้ตั้งค่า local secret แยกด้วย Wrangler ตามตัวเลือกของเวอร์ชันที่ใช้ หรือทดสอบขั้นตอน setup หลัง deploy

### 8) เผยแพร่เว็บ

```bash
wrangler deploy
```

เมื่อสำเร็จ Wrangler จะแสดง URL `https://...workers.dev` เปิด URL นั้น แล้วกรอกรหัสติดตั้ง `BOOTSTRAP_SECRET` เพื่อสร้างแอดมินคนแรก

**สำคัญ:** ตั้งค่า secret และสร้างฐานข้อมูลบน environment เดียวกับที่ deploy หากมีการทดสอบบน local อย่าสับสนกับฐานข้อมูล production

### 9) เพิ่มข้อมูลห้องเรียน

1. เข้าสู่ระบบแอดมิน
2. ไปที่ “ตั้งค่าและบัญชีแอดมิน” ตั้งชื่อห้องเรียน
3. ไปที่ “จัดการนักเรียน” แล้วเพิ่มเลขที่ ชื่อ–สกุล และชั้นเรียน
4. ไปที่ “ปฏิทินวันเรียน” เพิ่มวันหยุดพิเศษหรือวันเรียนชดเชยตามประกาศของโรงเรียน
5. ไปที่ “เช็กชื่อทำเวร” เลือกวัน ติ๊กสถานะให้ถูกต้อง แล้วบันทึก
6. ไปที่ “รายงานและสถิติ” เพื่อดาวน์โหลด CSV, JSON หรือพิมพ์/บันทึก PDF

## คำสั่งที่ใช้บ่อย

ดูสถานะ Worker:

```bash
wrangler deployments list
```

ดู log:

```bash
wrangler tail
```

ดูรายการฐานข้อมูล:

```bash

```

## กติกาการคำนวณ

- วันจันทร์–ศุกร์นับเป็นวันเรียนโดยปริยาย เว้นแต่กำหนดเป็นวันหยุด
- วันเสาร์–อาทิตย์นับเป็นวันหยุดโดยปริยาย เว้นแต่กำหนดเป็นวันเรียนชดเชย
- วันหยุดที่วันที่แน่นอน (เช่น 1 ม.ค., 6 เม.ย., ช่วงสงกรานต์ และวันสำคัญประจำปีที่ระบุไว้ในโค้ด) คำนวณอัตโนมัติ
- วันสำคัญที่เลื่อนตามปฏิทินจันทรคติหรือประกาศราชการในแต่ละปี ต้องตรวจสอบประกาศปัจจุบันและเพิ่มในปฏิทินเอง เพื่อไม่ให้ระบบอ้างวันหยุดผิด
- เปอร์เซ็นต์รายบุคคล = ทำเวรแล้ว ÷ (ทำเวรแล้ว + ไม่ทำเวร) × 100; รายการลา/ยกเว้นไม่นับเป็นวันที่มีหน้าที่
- วันที่ไม่มี daily record จะไม่ถูกนับเป็นไม่ทำเวร

## ความปลอดภัยและการดูแลรักษา

- รหัสผ่านถูกแฮชด้วย PBKDF2-HMAC-SHA-256 และ salt แยกบัญชี ไม่เก็บรหัสผ่านแบบข้อความธรรมดา
- Cookie เซสชันเป็น HttpOnly, Secure, SameSite=Lax และหมดอายุใน 7 วัน
- เก็บ `BOOTSTRAP_SECRET` ใน Cloudflare Worker Secrets เท่านั้น
- ปิดใช้งานบัญชีแอดมินที่ไม่ต้องการได้ แต่บัญชีที่กำลังเข้าสู่ระบบอยู่จะปิดตัวเองไม่ได้
- สำรองอัตโนมัติทุกวันประมาณ 18:15 UTC (01:15 น. เวลาไทยของวันถัดไป) ไปยัง R2
- ไฟล์สำรองมีข้อมูลนักเรียนและบันทึกย้อนหลัง ควรจำกัดสิทธิ์และไม่แชร์สาธารณะ
- CSV เปิดด้วย Excel ได้ แต่เป็น CSV ไม่ใช่ไฟล์ XLSX native

## ข้อจำกัดที่ควรรู้

- ชุดนี้ออกแบบสำหรับห้องเดียวตามข้อกำหนดเริ่มต้น
- รายงาน PDF ใช้คำสั่งพิมพ์ของเบราว์เซอร์: เลือก “Save as PDF”
- ปฏิทินวันหยุดอัตโนมัติครอบคลุมวันหยุดวันที่แน่นอนบางรายการเท่านั้น วันหยุดที่เปลี่ยนวันตามปีและวันหยุดโรงเรียนต้องตรวจสอบ/ตั้งค่าเอง
- ระบบ backup R2 เป็นสำเนาข้อมูล JSON รายวัน ไม่ใช่ native D1 point-in-time restore; เก็บสำเนาไว้มากกว่าหนึ่งที่และทดสอบกู้คืนก่อนใช้งานจริงระยะยาว
